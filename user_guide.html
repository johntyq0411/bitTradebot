Freqtrade BTC/USDT Bot — User Guide

✓ PAPER TRADING ONLY Freqtrade 2026.7 Python 3.11 BTC/USDT · 1h

This is an automated cryptocurrency paper-trading bot built on Freqtrade, an open-source trading framework. It runs an EMA crossover + RSI momentum strategy on the BTC/USDT pair using 1-hour candles, with no real money at risk — all trades are fully simulated.

⚠ Safety First dry_run: true is enforced in all configs. Exchange API keys are blank. The bot cannot place real orders. Do not add real API keys unless you fully understand the risks and have thoroughly validated the strategy.

Macro & Micro Structure (Multi-Factor Analysis)

To avoid false positives from basic technical signals, the bot filters entries through multiple dimensional factors:

graph LR subgraph Macro [1. Macro Filter] M1[1-Day Timeframe] --> M2{EMA20 > EMA50?} end subgraph Technical [2. Technical Setup] T1[1-Hour Timeframe] --> T2{EMA Crossover?} T1 --> T3{RSI 45 - 60?} end subgraph Micro [3. Micro Trigger] H1[Volume Activity] --> H2{Volume > 1.5x MA?} end Macro --> Entry Technical --> Entry Micro --> Entry Entry{All Conditions Met?} -->|Yes| Buy[🟢 Enter Trade]
  • Macro (Broader Trend): Checks daily (1d) trends to prevent buying in a macroeconomic downtrend (bear market filter).
  • Technical (Momentum & Volatility): EMA crossover defines the primary entry zone, while RSI filters entries to a healthy range to prevent buying overextended runs.
  • Micro (Volume Breakout): Requires a volume spike of 1.5x higher than the 24-hour average to confirm institutional support at entry.

Strategy — How It Works

What is an EMA?

An Exponential Moving Average gives more weight to recent prices. When the fast EMA (20) crosses above the slow EMA (50), it signals bullish momentum — price is trending up. When it crosses below, trend has reversed.

What is RSI?

The Relative Strength Index measures how fast price has moved. Values below 30 = oversold (often bounce up), above 70 = overbought (often pulls back). We filter entries to RSI 40–65 — a "healthy momentum" zone.

Entry & Exit Signal Logic

▲ BUY (Enter Long)

ALL conditions must be true on the same candle:

  • Macro: Daily EMA 20 is above Daily EMA 50
  • Technical: 1h EMA 20 crossed above 1h EMA 50
  • Technical: 1h RSI is between 45 and 60 (Tightened)
  • Micro: Volume is 1.5x higher than the previous 24h average

▼ SELL (Exit Long)

ANY condition triggers exit:

  • 1h EMA 20 crosses below 1h EMA 50, OR
  • 1h RSI exceeds 75 (overbought), OR
  • ROI target hit (aggressively taking partial gains), OR
  • Trailing stop hit (locks in profit after 2.5% run), OR
  • Hard Stop-loss at −5% triggered

Risk Management Rules

Minimal ROI Table

The bot auto-sells if profit reaches these thresholds (measured from trade open):

Time in TradeRequired Profit to ExitLogic
0 minutes (any time)5.0%Take 5% immediately if it spikes
2 hours +3.0%Accept lower target after 2h hold
4 hours +1.5%Just get out profitably after 4h

Stop-Loss

A hard stop at −4% from entry price. If BTC price drops 4% after entry, the position is closed immediately at market price, limiting the loss.

ℹ Example Trade Entry at $100,000. Stop-loss fires at $96,000 (−4%). ROI target (5%) fires at $105,000. The trade will exit whichever comes first — ROI, stoploss, or signal.

⚠ On Synthetic Data This backtest used GBM-generated data with σ=80% annual volatility — more chaotic than real BTC price movement. Real BTC has trend persistence and support/resistance structure that the EMA crossover exploits well. The −24% result on synthetic data is a stress-test, not a forecast.

The Core Problem: Loss/Win Asymmetry

Average winner (+1.93%) is smaller than average loser (−3.29%). This means even with a 60.7% win rate, the losses outweigh the wins. The fix is either:

  • Raise ROI targets — let winners run to 8–10% instead of 5%
  • Tighten the stop-loss — e.g. −2.5% instead of −4% (but risks more stopped trades)
  • Use a trailing stop — locks in gains as price rises

Best Practices — Safety

🔴 Never do these things
  • Never add real API keys to config_local.json while dry_run: true is set (the keys are unused, but it's unnecessary risk)
  • Never change dry_run to false without a minimum of 3 months paper trading validation
  • Never run with stake_amount: unlimited in live mode without position sizing study
  • Never skip backtesting when you change the strategy logic

Best Practices — Tuning & Hyperopt

How Hyperopt Works

flowchart LR A[Define parameter
search space] --> B[Freqtrade Hyperopt
runs N epochs] B --> C[Each epoch:
pick param values] C --> D[Run backtest
with those params] D --> E[Score result
using loss function] E --> F{Better than

Run Hyperopt

conda run -n freqtrade-btc freqtrade hyperopt \
  --config user_data/config_local.json \
  --strategy MultiFactorBtcStrategy \
  --strategy-path user_data/strategies \
  --hyperopt-loss SharpeHyperOptLoss \
  --epochs 200 \
  --spaces buy sell

curl -u $AUTH -X POST $BASE/start
