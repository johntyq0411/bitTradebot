# Technical Design Specification — Modest-Bohr V2

**Project:** Freqtrade BTC/USDT trend-following trading bot  
**Version:** 2.0 (fresh redesign)  
**Author:** John Tan  
**Date:** 2026-08-24  
**Status:** Draft — awaiting validation results  
**Goal:** A BTC-only, trend-following bot that generates positive expectancy after costs, with max drawdown ≤ 20%, suitable as a secondary income stream.

---

## 1. Glossary

See `CONTEXT.md` for full glossary. Key terms for this spec:

- **Strategy**: Freqtrade `IStrategy` class that produces entry/exit signals.
- **Regime**: Market condition classified by trend direction and volatility.
- **Signal**: Individual indicator-based condition that contributes to trade decision.
- **Walk-Forward Validation**: Rolling train/test windows across time to validate out-of-sample performance.
- **Expectancy**: Average trade P&L after costs, over many trades.

---

## 2. Architecture Overview

```
Data Layer
  ├── 1h OHLCV (primary, 2+ years)
  ├── 4h OHLCV (informative, for higher-timeframe context)
  └── Macro features (Fear & Greed, funding rate, OI, DXY, SPY — where available)

Regime Detection Layer
  └── Classifies each candle into: Bull Trending / Bear Trending / Sideways Low-Vol / Sideways High-Vol

Signal Engine Layer
  ├── Trend Signal (primary — MA structure, slope, ADX)
  ├── Momentum Signal (RSI, ROC, volume confirmation)
  └── [ML Signal — trend continuation probability, optional enhancement]

Decision Layer
  ├── Regime gate: only trade when regime favors strategy type
  ├── Signal combination: multiple confirmations required
  └── Entry/exit logic with confidence thresholds

Risk Management Layer
  ├── Position sizing (fixed fractional, 1-2% risk per trade)
  ├── Stop loss (ATR-based trailing)
  ├── Structural exit (trend break)
  └── Drawdown circuit breaker (≤20%)

Execution Layer
  ├── Freqtrade backtesting → dry-run → live
  └── Realistic cost modeling (0.1% fee + slippage)

Validation Layer
  ├── In-sample / out-of-sample split
  ├── Walk-forward across 8-10 folds
  ├── Lookahead-bias check (`freqtrade lookahead-analysis`)
  └── Sensitivity analysis (parameter perturbation)
```

## 4. Regime Detection Specification

### 4.1 Regime Definitions

| Regime | Criteria | Strategy Implication |
|---|---|---|
| **Bull Trending** | Price > 200-period SMA AND SMA slope > 0 AND ADX > 20 | Trend-following entries favored (long only) |
| **Bear Trending** | Price < 200-period SMA AND SMA slope < 0 AND ADX > 20 | Trend-following entries possible (short only, if supported) or sit out |
| **Sideways Low-Vol** | \|Price - SMA\| < 3% AND ATR low | No trend-following trades. Mean reversion or sit out. |
| **Sideways High-Vol** | \|Price - SMA\| < 3% AND ATR elevated | Transition possibility. Reduced position size or sit out. |

### 4.2 Implementation

The regime classifier from `user_data/scripts/regime_decompose.py` is the starting point. For the strategy, we need:

- **Trend indicator**: 200-period SMA (on 1h, ~8 days — may be too short; consider using 4h informative pair with 50-period SMA for ~10-day equivalent, or a longer period on 1h)
- **Trend slope**: SMA(t) vs SMA(t-24) on 1h
- **ADX**: 14-period, threshold 20 for "trend present"
- **Volatility**: ATR(14), compare to rolling median to classify high/low vol
- **Regime label per candle**, output as a column in the dataframe

### 4.3 Validation

- Backtest regime classifier: does it correctly identify the major regime shifts in our 2-year data?
- Check for whipsaw: how often does regime flip within short periods?
- Align with known historical events: did it correctly flag the Nov 2025 bear onset? The Mar 2025 bull start?

## 5. Signal Engine Specification

### 5.1 Trend Signal (Primary)

**Purpose:** Detect and confirm an established trend suitable for trend-following entry.

**Components:**

| Component | Implementation | Threshold |
|---|---|---|
| Price position | Close > SMA(200) on 1h, or equivalent on 4h informative | Must be above for long entries |
| SMA slope | SMA(200) now > SMA(200) 24 candles ago | Positive slope for long |
| ADX | 14-period ADX | > 20 (trend present) |
| Price structure | Higher high AND higher low over last 20 candles | Confirms uptrend structure |
| Momentum confirmation | RSI(14) > 50 AND rising, OR ROC(24) > 0 | At least one confirms momentum |
| Volume confirmation | Volume > median volume of last 50 candles | Optional but preferred |

**Signal score:** Each component contributes 1 point. Long entry requires:
- Minimum 4 of 5 components met (trend + at least one confirmation)
- All "hard" requirements met (price above SMA, SMA slope positive, ADX > 20)

### 5.2 Entry Trigger

```
LONG ENTRY:
  IF [Regime is Bull Trending] AND
     [Trend Signal score >= 4] AND
     [Price makes new higher high in last 5 candles] AND
     [No open trade] AND
     [Optional: ML confidence > threshold]
  THEN enter long on next candle

SHORT ENTRY:
  Not supported in V2 initially. Only long entries during bull trends.
```

### 5.3 Exit Logic

**Philosophy:** Let winners run, exit on trend breakdown or when risk limit hit. No fixed ROI target — structural exits only.

| Exit Type | Trigger | Implementation |
|---|---|---|
| **Trailing stop** | Price drops X ATR below highest close since entry | ATR(14) × 1.5 trailing. Recalculate each candle. |
| **Structural exit** | Price closes below SMA(50) or SMA(100) | Trend likely broken. Exit. |
| **Time stop** | No profit after N candles | Exit after 48 candles (2 days) if trade is at loss. |
| **Drawdown circuit breaker** | Equity drops 20% from peak | Stop all trading. Re-evaluate. |

### 5.4 Optional: ML Enhancement

**When to add:** After rule-based trend strategy shows positive expectancy in walk-forward.

**Prediction target:** Probability that price will be higher in 8-12 candles (8-12 hours), given current trend conditions. Binary classification: up / down.

**Features:** Technical indicators (RSI, EMA distances, ADX, ATR, volume), macro features where available, lagged returns at multiple horizons.

**How used:**
- Option A: Confidence modifier — only enter if ML predicts "up" with probability > threshold (e.g., 60%)
- Option B: Exit enhancer — tighten trailing stop if ML predicts trend exhaustion
- NOT: Entry/exit signals by themselves (ML alone underperformed rule-based in our Phase 0b results when sample was thin)

**Model:** LightGBM (current FreqAI setup), or logistic regression as simpler baseline.

## 6. Risk Management Specification

| Parameter | Value | Rationale |
|---|---|---|
| Stake currency | USDT | Stable, matches current setup |
| Stake amount | 1000 USDT (initial) | Paper trading amount; scale up later |
| Max open trades | 1 | BTC only, single position, conservative |
| Risk per trade | 1-2% of equity | Controlled exposure per trade |
| Stop loss type | ATR-based trailing, 1.5× ATR | Adapts to volatility, lets winners run |
| Structural exit | Close below SMA(50) or SMA(100) | Exit when trend broken |
| Time stop | 48 candles at loss | Avoid dead capital in non-trending conditions |
| Drawdown limit | 20% from peak equity | Circuit breaker — stop trading if hit |
| Position sizing | Fixed fractional (risk % of equity / stop distance) | Larger positions when stop is tight, smaller when volatile |

### 6.1 Costs to Model

| Cost | Rate | Notes |
|---|---|---|
| Trading fee | 0.1% per side | Binance spot default. Round-trip = 0.2% |
| Slippage | 0.05% | Conservative estimate for BTC on Binance |
| Spread | Implicit | Built into entry price |
| **Total round-trip** | **~0.25-0.3%** | Minimum move to break even per trade |

## 7. Validation Protocol

### 7.1 Walk-Forward Design

| Parameter | Value |
|---|---|
| Total backtest period | Aug 2024 – Aug 2026 (2 years) |
| Train window | 3 months (90 days) |
| Test window | 1 month (30 days) |
| Step | Roll forward 1 month |
| Number of folds | ~18 (24 months / 1 month step) — use at least 8-10 with diverse regimes |
| Minimum trades per fold | 10 (document if fewer) |

### 7.2 Validation Stages

```
Stage 1: Single backtest (exploratory)
  → Get first impression. Do NOT trust yet.

Stage 2: Lookahead analysis (freqtrade lookahead-analysis)
  → Verify no lookahead bias. Non-negotiable before trusting results.

Stage 3: In-sample / out-of-sample split
  → Split 70/30. If OOS performance collapses, strategy is overfit.

Stage 4: Walk-forward (full)
  → 8-10 folds across diverse regimes.
  → Aggregate: total trades, win rate, profit factor, Sharpe, max drawdown.
  → Check: OOS ≈ IS performance? Results consistent across regimes?

Stage 5: Sensitivity analysis
  → Perturb parameters ±10-20%. Does performance collapse?
  → If yes, the "optimum" is noise. Real edges have smooth landscapes.

Stage 6: Stress test
  → Double fees, add slippage. Does edge survive?
  → Test on completely held-out period.

Minimum bar for "has potential":
  ✓ Positive expectancy after costs in ≥70% of folds
  ✓ Total trades > 100 across all folds
  ✓ Max drawdown < 20% aggregate
  ✓ No single fold dominates (robustness)
  ✓ Passes lookahead analysis
```

### 7.3 Metrics to Track

| Metric | Why it matters |
|---|---|
| Total P&L (%) | Overall profitability |
| Number of trades | Statistical significance |
| Win rate (%) | Signal quality |
| Profit factor | Gross profit / gross loss — robust profitability metric |
| Sharpe ratio | Risk-adjusted return (note: can be misleading for trend strategies) |
| Max drawdown (%) | Risk measure — must be ≤ 20% |
| Average trade duration | Capital efficiency |
| Expectancy per trade (USDT) | Average profit per trade after costs |
| Regime-conditional performance | Does it work in all regimes or just one? |

## 9. Implementation Plan

### Phase 1: Data Preparation (Week 1)
- [ ] Download 4h data for full 2-year period
- [ ] Backfill macro features for full period
- [ ] Verify data completeness (no gaps)

### Phase 2: Regime Detection (Week 1-2)
- [ ] Finalize regime classifier implementation
- [ ] Backtest regime classifier accuracy
- [ ] Validate against known historical regimes

### Phase 3: Rule-Based Trend Strategy (Week 2-4)
- [ ] Implement `BtcTrendFollowingV2Strategy.py` (rule-based, no ML)
- [ ] Run single backtest (Stage 1)
- [ ] Run lookahead analysis (Stage 2)
- [ ] Run IS/OOS split (Stage 3)
- [ ] Run walk-forward (Stage 4)
- [ ] Parameter sensitivity (Stage 5)
- [ ] If positive: proceed to Phase 4
- [ ] If negative: redesign signals, repeat Phase 3

### Phase 4: ML Enhancement (Week 4-6, if Phase 3 succeeds)
- [ ] Set up FreqAI with proper feature engineering (no lookahead)
- [ ] Define prediction target (8-12 candle ahead direction)
- [ ] Train and backtest ML-enhanced strategy
- [ ] Compare ML vs rule-based baseline in walk-forward
- [ ] If ML improves: keep ML. If not: keep rule-based.

### Phase 5: Paper Trading (Week 6-10)
- [ ] Deploy best validated strategy in Freqtrade dry-run mode
- [ ] Monitor for 4-8 weeks
- [ ] Compare live vs backtest: do they match?
- [ ] If yes: consider live deployment. If no: investigate discrepancy.

### Phase 6: Live Deployment (Week 10+, if Phase 5 succeeds)
- [ ] Start with small stake
- [ ] Monitor weekly
- [ ] Retrain models if using ML
- [ ] Scale up as confidence grows
